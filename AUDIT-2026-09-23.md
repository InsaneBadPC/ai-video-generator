## Nalezené a vyřešené problémy

### 1. R2 credentials byly špatně rozložené (root cause, vyřešeno)
- `.env` mělo token v poli Access Key a ID tokenu ve Secret Key -> S3 podpis vždy chybový.
- Dle Cloudflare docs: **Access Key ID = ID API tokenu (32 hex)**, **Secret Access Key =
  SHA-256 hex hodnoty `cfut_…` tokenu**.
- Ověřeno výpočtem `sha256(cfut…) == 118668c9…4518` a E2E testem (upload/get/delete, presign).
- Vytvořen R2 bucket `ai-video-generator` (location EEUR). Nová pole v `.env`:
  `CLOUDFLARE_R2_ACCESS_KEY_ID`, `CLOUDFLARE_R2_SECRET_ACCESS_KEY`,
  `CLOUDFLARE_R2_BUCKET`, `CLOUDFLARE_R2_ENDPOINT`, `CLOUDFLARE_R2_TOKEN`.
- `storage_r2.py` čte nová jména; `config.yaml` má `storage.r2: true`.

### 2. Lokální repo bylo ZA VM (drift) — opraveno
- VM běžela novější produkčně otestovanou verzi než git repo. Chyběly v repu:
  - `orchestrator.py`: fix job_id (zachycení návratu `add_scene_job`), `math.ceil` chunking,
    předávání `duration`, R2 guard.
  - `dispatcher.py`: `_ensure_reference` (auto-reference fallback s hashlib digest),
    zpracování `duration`.
  - `queue.py`: `duration` sloupec + ALTER TABLE migrace.
  - `image_backend.py`: gradient + diagonální barevné pásy — lokální fallback projde QC
    variability jasu i při vyčerpané GPU kvótě.
  - `storyboard_generator.py`: deterministický `_fallback_scenes` při výpadku LLM/API.
  - `dashboard/*`: přihlašování (session cookie, login page), `POST /api/generate`
    (upload MP3 + obrázek), `GET /api/runs`, `GET /api/runs/{id}/download`, static
    PWA soubory (`icon.svg`, `manifest.webmanifest`).
  - `deploy/video-agent.service`: `PYTHONUNBUFFERED=1` + `-m pipeline.dispatcher`.
  - `requirements.txt`: `fastapi`, `uvicorn`.
  - `README.md`: sekce Dashboard (SSH tunel). `.env.example`: `DASHBOARD_USER/PASSWORD`.
- Vše staženo z VM do repa, sjednoceno R2 jméno (`CLOUDFLARE_R2_ACCESS_KEY_ID`),
  commit `1d2bea3` (override VM dashboard na nové jméno po pull).

### 3. Dashboard měl staré R2 jméno proměnné — opraveno
- `dashboard/server.py` ukazovalo `CLOUDFLARE_R2_ACCESS_KEY` místo `_ACCESS_KEY_ID`.
- Opraveno v repu i na VM; `/api/resources` nyní hlásí `CLOUDFLARE_R2_ACCESS_KEY_ID: true`.

### 4. Oprávnění / runtime
- VM venv nemělo `boto3` (bylo v requirements, chybělo) — doinstalováno.
- Služby přežily restart (`Restart=always`, `EnvironmentFile=/opt/video-agent/.env`,
  `ReadWritePaths` pro input/output/queue/state/logs/character_reference).

## Gap analýza (známé limity, neblokující)
1. **GPU kvóta ZeroGPU (HF Spaces)**: při vyčerpání selže `hf_wan` tier; fallback
   `local_kb` projde. `production-final.db` má 1 failed job přesně kvůli
   `"You have issued too many requests"` — chování je design (tier chain),
   ne chyba. Ověřeno navýšení retries (`max_retries: 4`).
2. **RAM 954 MiB na VM**: `assembly`/AI modely běží, ale velké video v jednom běhu
   může tlačit swap. Doporučeno držet clip délky ≤ 8–10 s a `chunk_s` nemaximalizovat.
3. **Fronta byla prázdná** (`queue/jobs.db` bez tabulky) — worker ji vytvoří při prvním
   jobu; `init()` je volán lazily. Naplněna reálným generováním z dashboardu.
4. **Dashboard port 8080** je vázán na localhost VM — přístup jen přes SSH tunel
   (záměrně, bezpečně).
5. **session cookie** je z hesel (ne náhodný token) — dostatečné pro lokální tunel,
   ne pro veřejný internet.
6. **Telegram notify** vypnut (`TELEGRAM_BOT_TOKEN/CHAT_ID` prázdné) — podle zadání
   volitelné; pipeline ho nechá přeskočit.
